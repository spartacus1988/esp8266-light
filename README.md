# Управление светом на Wemos D1 mini (ESP8266) + MicroPython

Прошивка для платы **Wemos D1 mini** с подключённым **модулем реле**: свет
включается и выключается с телефона/компьютера через веб-страницу, а сам код
загружается и правится **по Wi-Fi** (WebREPL) — USB-кабель нужен только один раз,
для самой установки MicroPython.

Проект переписан на основе репозитория
[spartacus1988/ampy_esp_8266_switch_light](https://github.com/spartacus1988/ampy_esp_8266_switch_light)
(там был веб-сервер на Python/MicroPython и загрузка кода по USB через `ampy`).

---

## Важно про Bluetooth

У чипа **ESP8266 нет Bluetooth вообще** — в нём есть только радио Wi-Fi.
Поэтому «включать свет по блютузу» на Wemos D1 mini невозможно без внешнего
модуля. В этом проекте управление сделано **по Wi-Fi**, как и просилось после
уточнения.

Если Bluetooth всё-таки нужен — есть два пути:

* **внешний модуль HC-05/HC-06**, подключённый к пинам TX/RX (GPIO1/GPIO3)
  платы — тогда MicroPython общается с ним по UART, и свет переключается с
  телефона по блютузу;
* **плата на ESP32** — у неё Bluetooth встроенный, но это уже другая плата и
  другая распиновка.

## Схема подключения

```
Wemos D1 mini            Модуль реле
--------------            -----------------
D1  (GPIO5)  ----------> IN
5V            ----------> VCC   (или JD-VCC, см. инструкцию к модулю)
GND           ----------> GND

                       COM  ---[ выключатель / автомат ]---  НАГРУЗКА (лампа)
                       NO   --------------------------------^
                       NC   (не используется)
```

* Реле коммутирует **фазу** 220 В в разрыв цепи питания нагрузки.
* ⚠️ **Работа с сетью 220 В опасна для жизни.** Если не уверены — соберите
  схему под присмотром специалиста и обязательно используйте изоляцию.
* Если модуль реле переключается «наоборот» (свет включается, когда должен
  выключаться) — в `config.py` переключите `RELAY_ACTIVE_HIGH`.
* Встроенный светодиод D4 (GPIO2) индицирует состояние: светится, когда свет
  включён.

## Установка (один раз, по USB)

### Шаг 1. Прошивка MicroPython

Нужен USB-кабель и Python 3.

**Windows:**

```powershell
.\flash.ps1
# или с указанием порта:
.\flash.ps1 -Port COM3
```

**Linux/macOS (или вручную):**

```sh
pip install -U esptool

# скачать образ MicroPython ESP8266_GENERIC v1.29.0:
curl -LO https://micropython.org/resources/firmware/ESP8266_GENERIC-20260824-v1.29.0.bin
# (список версий: https://micropython.org/download/ESP8266_GENERIC/)

python -m esptool --chip esp8266 erase_flash
python -m esptool --chip esp8266 --baud 460800 write_flash --flash-size=detect 0 \
    ESP8266_GENERIC-20260824-v1.29.0.bin
```

> В esptool v5 опция называется `--flash-size`, в esptool v4 — `--flash_size`
> (если старая версия ругается на `--flash-size`, просто замените имя).
> Скрипт `flash.ps1` определяет это сам.

Если плата не определяется — зажмите кнопку **FLASH** на D1 mini и нажмите
**RST**, после чего отпустите FLASH.

### Шаг 2. Первая загрузка кода

После прошивки WebREPL ещё **не запущен** (запускает его наш `boot.py`), поэтому
самые первые файлы надо положить на плату одним из двух способов.

#### Вариант А — через `mpremote` (рекомендуется)

```sh
pip install mpremote

mpremote cp config.py :config.py
mpremote cp boot.py   :boot.py
mpremote cp main.py   :main.py
```

Если устройство не находится автоматически, укажите порт:

```sh
mpremote connect COM3 cp config.py :config.py     # Windows
mpremote connect /dev/ttyUSB0 cp config.py :config.py   # Linux
```

(Тот же результат даёт **Thonny**: выберите интерпретатор *MicroPython
(generic)*, порт COMx, и сохраните каждый из трёх файлов «on MicroPython
device».)

#### Вариант Б — поднять сеть и WebREPL из терминала (USB)

1. Откройте последовательный порт на **115200** (PuTTY / Thonny / монитор
   порта) и нажмите Enter — должен появиться `>>>`.
2. Выполните построчно (значения — те же, что в `config.py`):

   ```python
   import network
   ap = network.WLAN(network.WLAN.IF_AP)
   ap.active(True)
   ap.config(ssid="esp-light", security=network.AUTH_WPA_WPA2_PSK, key="light1234")
   import webrepl
   webrepl.start(password="esp8266")
   ```

   После последней строки появится `WebREPL server started on http://192.168.4.1:8266/`.
3. Не закрывая порт, подключитесь к Wi-Fi сети `esp-light` (пароль `light1234`)
   и запустите загрузку файлов — `.\upload.ps1` или `./copy_to_esp.sh`.
4. Нажмите кнопку **RESET** на плате.

> Альтернатива: `import webrepl_setup` — интерактивный мастер. Он напишет в
> `webrepl_cfg.py` и `boot.py` свои строки, поэтому после него всё равно
> нужно загрузить наши три файла (сеть он не поднимает — шаг 2 выше всё равно
> понадобится).

## Загрузка кода по Wi-Fi (дальше — только так)

> Секция действует **после «Шага 2»**. Пока `boot.py` не лежит на плате,
> сети `esp-light` не существует (в Варианте Б сеть поднимается вручную —
> тогда загрузка файлов и есть завершение Шага 2). Вариант А: сначала
> положите все три файла по USB, нажмите RESET, и дальше работайте только
> через Wi-Fi.

1. Подключите телефон/компьютер к Wi-Fi сети платы:
   * сеть: **`esp-light`**,
   * пароль: **`light1234`** (задаётся в `config.py`).
2. Запустите загрузку:

   **Windows:**

   ```powershell
   .\upload.ps1
   # пароль отличается от config.py:
   .\upload.ps1 -Password mypass
   ```

   **Linux/macOS:**

   ```sh
   ./copy_to_esp.sh                # адрес 192.168.4.1, пароль из config.py
   ./copy_to_esp.sh 192.168.4.1    # свой адрес
   ```

   Скрипт сам скачает официальный клиент `webrepl_cli.py` и загрузит
   `config.py`, `boot.py`, `main.py`.

3. Перезагрузите плату, чтобы файлы подхватились:
   * если `main.py` уже запускался — откройте `http://192.168.4.1/?reset=1`;
   * если это **первая** загрузка (веб-сервер ещё ни разу не работал) —
     просто нажмите кнопку **RESET** на плате.

> ⚠️ Одновременно может работать **только одно** подключение WebREPL. Закройте
> браузерную веб-консоль, если она открыта, прежде чем запускать скрипт
> загрузки.

### Ручная загрузка (если нужно)

```sh
python webrepl_cli.py -p esp8266 config.py 192.168.4.1:/config.py
python webrepl_cli.py -p esp8266 boot.py   192.168.4.1:/boot.py
python webrepl_cli.py -p esp8266 main.py   192.168.4.1:/main.py
# скачать файл с платы обратно (нужны оба аргумента — «куда положить»):
python webrepl_cli.py -p esp8266 192.168.4.1:/main.py ./main.py
```

Клиент `webrepl_cli.py` лежит в
[github.com/micropython/webrepl](https://github.com/micropython/webrepl)
(скрипты `upload.ps1` / `copy_to_esp.sh` скачивают его сами).

Интерактивный Python-промпт по Wi-Fi удобнее открывать в браузере:
<http://micropython.org/webrepl> → адрес `ws://192.168.4.1:8266`, пароль.
Клиент должен открываться по **http**, а не https (браузеры блокируют
`ws://` со страниц на `https://`).

> На Windows режим «промпт» у `webrepl_cli.py` не работает (нужен POSIX),
> поэтому для REPL используйте браузер. Загрузка файлов (`put`/`get`) на
> Windows работает исправно.

## Управление светом

Откройте в браузере: **<http://192.168.4.1/>**

* большая кнопка включения/выключения,
* индикатор состояния (зелёный — свет включён),
* показание АЦП на входе A0 (0…1023),
* кнопка перезагрузки платы.

### API (для умного дома, Node-RED, сценариев)

```
GET /api               -> {"relay":"on","adc":512,"ip":"192.168.4.1"}
GET /api?relay=on      -> включить
GET /api?relay=off     -> выключить
GET /?relay=on         -> включить (и вернуть страницу)
GET /?reset=1          -> перезагрузить плату
```

Пример из терминала:

```sh
curl "http://192.168.4.1/api?relay=on"
```

## Настройки — `config.py`

```python
AP_SSID = "esp-light"          # имя Wi-Fi сети платы
AP_PASSWORD = "light1234"      # пароль сети, 8..63 символов

WEBREPL_PASSWORD = "esp8266"   # пароль доступа к коду по Wi-Fi, 4..9 символов!
WEBREPL_PORT = 8266

RELAY_PIN = 5                  # D1 -> IN модуля реле
LED_PIN = 2                    # D4 -> встроенный светодиод

RELAY_ACTIVE_HIGH = True       # False, если модуль реле инверсный
LED_ACTIVE_LOW = True          # True: светодиод D4 светится при LOW (так и есть на D1 mini)

HTTP_PORT = 80
DEVICE_NAME = "Свет"           # заголовок страницы
```

После правки `config.py` загрузите его на плату (`.\upload.ps1`) и перезагрузите.

## Отладка и восстановление

* **Промпт по USB:** 115200. Он работает **одновременно** с WebREPL (разные
  слоты дублирования терминала), так что кабель можно не вынимать.
  Единственная загвоздка: пока крутится `main.py` (бесконечный цикл
  веб-сервера) промпт занят. Нажмите **Ctrl+C** — вы окажетесь в `>>>`,
  **Ctrl+D** — перезагрузка со свежим запуском `boot.py` + `main.py`.
* **Проверка, что всё работает:** подключитесь к сети `esp-light`, откройте
  `http://192.168.4.1/` и `http://192.168.4.1/api`.
* **Плата не создаёт сеть `esp-light`** — либо `boot.py`/`main.py` ещё не
  загружены (см. Шаг 2), либо повреждена файловая система. Восстановление:

  ```sh
  python -m esptool --chip esp8266 erase_flash
  # затем заново: .\flash.ps1  и Шаг 2 (загрузка файлов)
  ```

* **Забыли пароль WebREPL** — он всегда равен `WEBREPL_PASSWORD` в `config.py`.
  Если до платы не добраться, сотрите флеш (команда выше) и прошьте заново.
* **Код не обновился** — файлы загружены, но плата не перезагружалась.
  Откройте `http://192.168.4.1/?reset=1` или нажмите RESET.

## Безопасность

* Сеть платы защищена WPA2, доступ к коду — паролем WebREPL.
* **WebREPL не шифрует трафик** и предназначен только для локальной сети.
  Не пробрасывайте порт 8266 наружу и не подключайтесь к нему через чужие
  Wi-Fi сети.
* Не используйте пароли по умолчанию, если плата окажется в общей сети.

## Что изменилось по сравнению с оригинальным репозиторием

| Было (`ampy_esp_8266_switch_light`) | Стало |
|---|---|
| Веб-сервер, парсинг запросов через `request.find('/?LED=ON')` | Нормальный разбор HTTP-запроса, коды ответов, редиректы, JSON API |
| Загрузка кода по USB через `ampy` (`copy_to_esp.sh`) | Загрузка по Wi-Fi через WebREPL (`upload.ps1`, `copy_to_esp.sh`) |
| `boot.py` гасил Wi-Fi и отключал WebREPL | `boot.py` поднимает свою Wi-Fi-сеть и запускает WebREPL |
| Автоуправление реле по ADC (A0 > 512) до первого запроса | Убрано: A0 только показывается на странице (реле управляется только веб-интерфейсом) |
| Ответ браузеру без HTTP-заголовков | Полноценные заголовки, `Content-Type`, `Content-Length` |
| Настройки разбросаны по коду | Единый файл `config.py` |
